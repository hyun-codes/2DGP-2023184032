# 소닉 애니메이션 뷰어 제품 요구사항 문서(PRD)

## 1. 문서 개요

- 제품명: 소닉 애니메이션 뷰어
- 대상 경로: `Labs/LEC09`
- 실행 파일: `sonic_animation_viewer.py`
- 스프라이트 시트: `sonic-sprite.png`
- 개발 언어: Python
- 그래픽 라이브러리: `pico2d`
- 문서 목적: `PRE-PRD.md`의 아이디어를 구현 가능하고 검증 가능한 개발 요구사항으로 구체화한다.

> `PRE-PRD.md`에는 스프라이트 이미지가 `sonic sprite.png`로 기재되어 있으나, 저장소에 실제로 존재하는 파일명인 `sonic-sprite.png`를 기준으로 한다.

## 2. 제품 목표

`sonic-sprite.png`에 포함된 소닉의 모든 애니메이션 동작을 1200 × 800 화면에서 순서대로 보여 주는 자동 재생 뷰어를 개발한다. 이동이 포함된 동작은 프레임 재생과 동시에 캐릭터의 화면 위치도 바꾸고, 제자리 동작은 화면 중앙에서 재생한다. 각 동작은 5회 반복 재생하고, 동작 사이에는 1초간 마지막 프레임과 위치를 유지한다. 마지막 동작까지 재생한 뒤에는 첫 동작으로 돌아가 이 과정을 무한 반복한다.

## 3. 사용자 시나리오

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 뷰어가 창을 열고 스프라이트 이미지를 불러온다.
3. 첫 번째 소닉 동작이 확대되어 재생되며, 이동 동작이면 프레임 변화와 함께 화면 위치도 연속적으로 바뀐다.
4. 해당 동작이 5회 재생되면 마지막 프레임과 현재 위치에서 1초간 멈춘다.
5. 다음 동작이 같은 방식으로 재생된다.
6. 모든 동작의 재생이 끝나면 첫 번째 동작부터 다시 재생된다.
7. 사용자가 창 닫기 버튼 또는 `ESC` 키를 누르면 프로그램이 정상 종료된다.

## 4. 범위

### 4.1 포함 범위

- 스프라이트 시트에서 소닉 캐릭터의 프레임 영역을 잘라서 표시
- 연속된 프레임을 동작 단위로 묶어 애니메이션 재생
- 동작별 5회 반복 횟수 관리
- 동작 전환 전 1초 대기
- 전체 동작 목록의 무한 순환
- 작은 원본 프레임을 알아보기 쉽도록 확대 표시
- 걷기, 달리기, 구르기 3종의 경과 시간 기반 화면 이동
- 화면 경계에서의 진행 방향 및 스프라이트 방향 반전
- 나머지 동작 7종의 화면 중앙 제자리 재생
- 종료 이벤트 처리
- 현재 동작 및 프레임 진행을 관리하는 메인 루프

### 4.2 제외 범위

- 사용자 조작으로 소닉을 이동시키는 게임 기능
- 키보드로 동작을 선택하거나 재생 속도를 변경하는 기능
- 충돌 처리, 물리 효과, 사운드 및 배경 음악
- 별도 설정 파일 또는 외부 데이터 파일
- 스프라이트 시트의 제목, 제작자 표기, 장식 문자 및 소닉이 아닌 캐릭터의 재생
- 스프라이트 이미지 편집 또는 신규 이미지 생성

## 5. 자산 분석 및 동작 정의

### 5.1 원본 자산

- 파일명: `sonic-sprite.png`
- 이미지 크기: 399 × 525 픽셀
- 픽셀 형식: 투명도를 포함한 32비트 ARGB

### 5.2 동작 분류 기준

- 스프라이트 시트에서 서로 인접하며 하나의 움직임으로 자연스럽게 이어지는 소닉 프레임들을 하나의 동작으로 정의한다.
- 동작은 시트의 위쪽에서 아래쪽으로, 같은 높이에서는 왼쪽에서 오른쪽으로 등장하는 순서로 재생한다.
- 좌우 반전으로만 중복되는 동작은 원본 시트에 실제 프레임이 각각 존재하면 별도 동작으로 취급한다.
- 한 장으로 구성된 정지 자세도 소닉의 독립된 자세라면 1프레임 동작으로 포함한다.
- 제목, 크레딧, 장식 그림과 소닉이 아닌 캐릭터는 동작 목록에서 제외한다.
- 각 프레임은 `(x, y, width, height)` 형태의 잘라내기 영역으로 정의한다.
- 모든 동작 및 프레임 정보는 `sonic_animation_viewer.py` 안의 상수 또는 자료구조에 선언한다.
- 구현 과정에서 동작별 이름, 프레임 수, 잘라내기 좌표를 코드 주석으로 남겨 누락 여부를 확인할 수 있게 한다.

### 5.3 위치 이동 분류

동작별 이동 유형과 속도는 동작 자료구조에 함께 선언한다. 속도의 단위는 초당 픽셀이다.

| 동작 | 이동 유형 | 기본 속도 | 표시 방식 |
|---|---|---:|---|
| 걷기와 달리기 전환 | 수평 이동 | 120 | 왼쪽에서 시작해 화면 경계에서 방향 반전 |
| 빠르게 달리기 | 수평 이동 | 280 | 왼쪽에서 시작해 화면 경계에서 방향 반전 |
| 급정지 | 제자리 | 0 | 화면 중앙 |
| 구르기 | 수평 이동 | 220 | 왼쪽에서 시작해 화면 경계에서 방향 반전 |
| 회전 진입 | 제자리 | 0 | 화면 중앙 |
| 스프링과 착지 | 제자리 | 0 | 화면 중앙 |
| 특수 동작 | 제자리 | 0 | 화면 중앙 |
| 피격과 쓰러짐 | 제자리 | 0 | 화면 중앙 |
| 균형 잡기와 밀기 | 제자리 | 0 | 화면 중앙 |
| 위아래 보기 | 제자리 | 0 | 화면 중앙 |

- 이동 동작은 걷기와 달리기 전환, 빠르게 달리기, 구르기의 총 3종이다.
- 나머지 7종은 화면 중앙에서 제자리 재생한다.
- 오른쪽 경계에 도달하면 왼쪽으로, 왼쪽 경계에 도달하면 오른쪽으로 진행 방향을 바꾼다.
- 왼쪽으로 이동할 때는 스프라이트도 수평 반전하여 이동 방향과 바라보는 방향을 일치시킨다.

## 6. 기능 요구사항

### FR-01. 캔버스 생성

- 프로그램 시작 시 `pico2d` 캔버스를 한 번 생성한다.
- 기본 캔버스 크기는 1200 × 800 픽셀로 한다.
- 캔버스 크기는 코드 상수로 관리한다.

### FR-02. 이미지 로딩

- 실행 파일과 같은 디렉터리의 `sonic-sprite.png`를 불러온다.
- 이미지 파일 경로는 코드 상수로 관리한다.
- 정상 실행 중 이미지를 반복해서 다시 불러오지 않는다.

### FR-03. 전체 동작 등록

- 5장의 스프라이트 프레임만 임의로 고르는 것이 아니라, 5.2절의 기준을 만족하는 모든 소닉 동작을 등록한다.
- 각 동작 데이터는 동작 이름, 프레임 영역 목록, 이동 유형과 이동 속도를 포함한다.
- 프레임 크기가 서로 다른 동작을 지원해야 한다.

### FR-04. 프레임 애니메이션

- 현재 동작의 프레임을 정해진 순서대로 한 장씩 표시한다.
- 프레임 간격의 기본값은 0.1초(초당 10프레임)로 한다.
- 프레임 간격은 코드 상수로 관리하여 쉽게 조정할 수 있어야 한다.
- 마지막 프레임 다음에는 첫 프레임으로 돌아가 한 번의 동작 반복을 완성한다.

### FR-05. 동작별 5회 반복

- 각 동작은 정확히 5회 반복한 후 다음 상태로 넘어간다.
- 반복 횟수는 마지막 프레임에서 첫 프레임으로 전환할 때 1 증가한다.
- 1프레임 동작은 해당 프레임을 프레임 간격 동안 표시한 것을 1회 재생으로 계산한다.
- 반복 횟수 5는 코드 상수로 관리한다.

### FR-06. 동작 간 대기

- 5회 재생을 마치면 마지막 프레임을 화면에 유지한 채 정확히 1초간 대기한다.
- 대기 중에는 애니메이션 프레임, 반복 횟수, 화면 위치와 진행 방향을 변경하지 않는다.
- 대기 중에도 창 닫기 및 `ESC` 입력에 즉시 반응해야 한다.
- 대기 시간 1초는 코드 상수로 관리한다.

### FR-07. 다음 동작 전환

- 1초 대기가 끝나면 다음 동작의 첫 프레임으로 전환한다.
- 전환 시 프레임 인덱스, 동작 반복 횟수, 동작 경과 시간과 진행 방향을 초기화한다.
- 이동 동작은 왼쪽 시작 위치에서, 제자리 동작은 화면 중앙에서 시작한다.
- 마지막 동작 다음에는 첫 번째 동작으로 돌아간다.

### FR-08. 무한 반복

- 사용자가 종료하기 전까지 전체 동작 목록을 계속 순환 재생한다.
- 전체 목록이 한 바퀴 끝나더라도 캔버스를 닫거나 이미지를 다시 로딩하지 않는다.

### FR-09. 화면 표시

- 현재 프레임의 가로세로 비율을 유지한다.
- 가장 큰 프레임도 캔버스 경계를 벗어나지 않는 범위에서 충분히 확대한다.
- 확대 배율은 기본 4배로 하되, 프레임이 캔버스를 벗어나는 경우 자동으로 축소한다.
- 제자리 동작은 투명 여백이 아니라 캐릭터 프레임 영역의 중심이 캔버스 중앙에 오도록 표시한다.
- 이동 동작도 확대된 프레임 전체가 캔버스 경계를 벗어나지 않도록 위치 경계를 계산한다.
- 배경색은 소닉 캐릭터의 파란색 및 투명 영역과 구분되는 단색을 사용한다.

### FR-10. 동작별 위치 이동

- 걷기, 달리기, 구르기 3종은 애니메이션 재생과 동시에 위치를 갱신한다.
- 프레임 전환 시간과 위치 이동 시간은 서로 독립적으로 실제 경과 시간을 사용한다.
- 수평 위치는 `이동 속도 × 경과 시간 × 진행 방향`으로 계산한다.
- 화면 좌우 경계에 도달하면 위치가 캔버스 밖으로 나가지 않도록 보정하고 진행 방향을 반전한다.
- 진행 방향이 왼쪽이면 스프라이트를 수평 반전한다.
- 나머지 7종은 이동하지 않고 화면 중앙에서 재생한다.
- 대기 상태에서는 마지막 프레임과 마지막 위치를 1초간 고정한다.

### FR-11. 이벤트 및 종료 처리

- 매 메인 루프에서 운영체제 이벤트를 처리한다.
- 창 닫기 이벤트 또는 `ESC` 키 입력 시 실행 루프를 종료한다.
- 실행 루프 종료 후 `close_canvas()`를 호출하여 정상 종료한다.

### FR-12. 단일 실행 파일

- 직접 작성하는 런타임 소스 코드는 `sonic_animation_viewer.py` 한 파일로 제한한다.
- 별도 Python 모듈, 설정 파일, 좌표 데이터 파일을 추가하지 않는다.
- 제공된 `sonic-sprite.png`는 프로그램 자산이므로 단일 소스 파일 제약에서 제외한다.

## 7. 상태 및 데이터 요구사항

### 7.1 필수 상태

프로그램은 최소한 다음 상태를 관리해야 한다.

- 실행 여부
- 현재 동작 인덱스
- 현재 프레임 인덱스
- 현재 동작 반복 횟수
- 현재 상태: `PLAYING` 또는 `PAUSED_BETWEEN_ACTIONS`
- 마지막 프레임 갱신 시각
- 현재 화면 좌표
- 현재 진행 방향
- 마지막 위치 갱신 시각
- 동작 간 대기 시작 시각

### 7.2 시간 처리

- 애니메이션, 위치 이동과 대기 시간은 누적 프레임 수가 아닌 경과 시간으로 판정한다.
- 프레임 전환과 위치 이동은 각각의 시각 상태를 사용하여 독립적으로 갱신한다.
- `delay(1.0)`처럼 이벤트 처리를 막는 긴 블로킹 대기는 사용하지 않는다.
- 컴퓨터 성능에 따라 메인 루프 횟수가 달라져도 재생 속도와 대기 시간이 크게 달라지지 않아야 한다.

## 8. 비기능 요구사항

### NFR-01. 가독성

- 캔버스 크기, 프레임 간격, 반복 횟수, 대기 시간, 확대 배율, 이미지 경로는 이름이 명확한 상수로 선언한다.
- 동작 데이터, 이벤트 처리, 상태 갱신, 화면 그리기의 책임을 구분한다.
- 동작 좌표와 상태 전환에는 의도를 설명하는 간결한 주석을 작성한다.

### NFR-02. 안정성

- 정상 실행 중 프레임 인덱스 또는 동작 인덱스 범위를 벗어나지 않아야 한다.
- 프레임 크기가 서로 달라도 왜곡되거나 화면 밖으로 잘리지 않아야 한다.
- 이동 중 확대된 프레임이 화면 경계를 넘어가지 않아야 한다.
- 경계에서 방향을 반복해서 바꾸더라도 위치가 유효 범위를 벗어나지 않아야 한다.
- 대기 상태에서는 위치가 변하지 않아야 한다.
- 장시간 반복 실행해도 반복 횟수 및 상태 전환 오류가 없어야 한다.

### NFR-03. 실행 환경

- 저장소에서 사용하는 Python 및 `pico2d` 환경에서 실행 가능해야 한다.
- 실행 기준 디렉터리는 `Labs/LEC09`로 한다.
- 운영체제별 절대 경로에 의존하지 않는다.

### NFR-04. 개발 이력

- 개발은 한 번에 완성하지 않고 최소 20개의 독립적인 단계로 나눈다.
- 각 단계가 끝날 때 프로그램은 가능한 범위에서 실행 가능한 상태를 유지한다.
- 각 단계는 하나의 목적만 가지며 별도 Git 커밋으로 기록할 수 있어야 한다.

## 9. 27단계 개발 및 커밋 계획

| 단계 | 구현 내용 | 완료 기준 | 권장 커밋 메시지 |

| 5 | 단일 프레임 잘라 그리기 | 소닉 프레임 하나가 화면에 표시됨 | `첫 소닉 프레임 표시` |
| 6 | 화면 중앙 정렬 | 크기가 다른 프레임도 중앙에 표시됨 | `스프라이트 화면 중앙 정렬` |
| 7 | 확대 배율 적용 | 작은 프레임이 비율을 유지하며 확대됨 | `소닉 프레임 확대 표시` |
| 8 | 화면 경계 기반 자동 축소 | 큰 프레임이 화면 밖으로 잘리지 않음 | `프레임 크기 자동 보정` |

| 10 | 첫 동작 프레임 데이터 등록 | 첫 동작의 모든 프레임 좌표가 정의됨 | `첫 소닉 동작 데이터 등록` |
| 11 | 첫 동작 애니메이션 구현 | 첫 동작 프레임이 순서대로 재생됨 | `첫 동작 프레임 재생` |

| 13 | 동작 1회 완료 판정 | 마지막 프레임 후 반복 횟수가 증가함 | `동작 반복 횟수 계산` |

| 16 | 비차단 1초 대기 구현 | 이벤트 처리를 유지하며 1초간 멈춤 | `동작 전환 대기 구현` |
| 17 | 두 번째 동작 및 전환 구현 | 첫 동작 대기 후 두 번째 동작이 재생됨 | `다음 소닉 동작 전환` |
| 18 | 전체 소닉 동작 데이터 등록 | 분류 기준에 맞는 모든 동작이 목록에 존재함 | `전체 소닉 동작 데이터 등록` |
| 19 | 마지막에서 처음으로 순환 | 전체 동작 재생 후 첫 동작으로 돌아감 | `전체 동작 무한 순환` |
| 20 | 전체 검증 및 정리 | 모든 수용 기준을 만족하고 불필요한 코드가 없음 | `소닉 애니메이션 뷰어 최종 검증` |
| 21 | 초기 동작별 이동 정보 등록 | 초기안의 이동 8종과 제자리 2종의 유형·속도가 정의됨 | `동작별 이동 유형과 속도 정의` |
| 22 | 경과 시간 기반 수평 이동 | 이동과 프레임 재생이 동시에 진행되고 경계에서 방향을 바꿈 | `이동 애니메이션 위치 갱신` |
| 23 | 초기 점프와 대기 위치 처리 | 초기안의 점프 궤적을 표시하고 대기 중 마지막 위치를 유지함 | `점프 궤적과 대기 위치 고정` |
| 24 | 초기 이동 요구사항 문서화 및 검증 | 초기 코드와 Markdown의 이동 조건이 일치함 | `이동 애니메이션 요구사항 반영` |
| 25 | 이동 동작 재분류 | 걷기, 달리기, 구르기만 이동 동작으로 지정됨 | `이동 동작을 걷기 달리기 구르기로 제한` |
| 26 | 나머지 동작 중앙 고정 | 이동하지 않는 7종과 불필요한 점프 이동 코드가 정리됨 | `나머지 동작을 화면 중앙에 고정` |
| 27 | 변경 요구사항 문서화 및 검증 | 코드와 Markdown의 이동 3종·제자리 7종 조건이 일치함 | `이동 동작 제한 요구사항 반영` |

21~24단계는 이동 범위를 넓게 잡았던 초기 구현 이력이다. 최종 요구사항은 25~27단계에서 이를 수정한 것으로, 걷기·달리기·구르기 3종만 이동하고 나머지 7종은 제자리 재생한다.

단계별 커밋에서는 해당 단계와 무관한 변경을 함께 포함하지 않는다. 좌표 등록량이 많아 검토가 어려우면 18단계를 동작 그룹별 여러 커밋으로 더 세분화할 수 있으며, 전체 단계 수는 20개보다 많아도 된다.

## 11. 검증 방법

### 11.1 정적 검토

- 실행 파일 외에 추가 Python 파일이나 외부 설정 파일이 없는지 확인한다.
- 동작 자료구조에 이름, 프레임 영역 목록, 이동 유형과 속도가 모두 존재하는지 확인한다.
- 이동 동작이 3종이고 제자리 동작이 7종인지 확인한다.
- 인덱스, 반복 횟수, 시간, 위치와 진행 방향이 명확한 상태 변수로 관리되는지 확인한다.

### 11.2 수동 실행 검증

- 프로그램을 실행해 첫 동작의 프레임 재생과 수평 이동이 동시에 진행되는지 확인한다.
- 생성된 캔버스의 크기가 1200 × 800인지 확인한다.
- 걷기보다 빠르게 달리기와 구르기 동작이 더 빠르게 이동하는지 확인한다.
- 캐릭터가 양쪽 화면 경계에서 잘리지 않고 방향을 바꾸는지 확인한다.
- 왼쪽 이동 시 스프라이트가 수평 반전되는지 확인한다.
- 급정지, 회전 진입, 스프링과 착지, 특수 동작, 피격과 쓰러짐, 균형 잡기와 밀기, 위아래 보기 동작이 화면 중앙에서 재생되는지 확인한다.
- 한 동작의 반복 횟수를 직접 세어 정확히 5회인지 확인한다.
- 5회째 마지막 프레임과 현재 위치에서 약 1초간 멈추는지 확인한다.
- 대기 중 `ESC`를 눌러 즉시 종료되는지 확인한다.
- 여러 크기의 프레임이 찌그러지거나 잘리지 않는지 확인한다.
- 마지막 동작 이후 첫 동작으로 되돌아오는지 확인한다.
- 최소 2회의 전체 순환 동안 상태 전환 오류가 없는지 확인한다.

### 11.3 데이터 누락 검증

- 원본 이미지를 위에서 아래, 왼쪽에서 오른쪽으로 확인한다.
- 각 소닉 프레임이 정확히 한 동작에 포함되었는지 대조한다.
